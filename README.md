Разработайте совместно с ИИ сервис для бронирования календаря

Как это должно работать: https://files.hexlet.app/a/2ipc5m

## Сценарии

### Сценарий владельца календаря

1. **Создание типа встречи**: Владелец создает новый тип встречи, указывая название (например, «Консультация»), описание и длительность (например, 30 минут или 1 час). После сохранения тип встреча появляется в списке доступных вариантов для гостей.

2. **Просмотр предстоящих встреч**: Владелец видит список всех **запланированных** встреч любых типов на ближайшие 14 дней. Список обновляется при каждом новом бронировании гостем. Содержит дату, время, тип встречи.

### Сценарий гостя

1. **Вход без регистрации**: Гость открывает приложение и сразу попадает на главный экран. Регистрация не требуется — доступ гарантирован через гостиный режим.

2. **Выбор типа встречи**: Отображается список типов встреч, созданных владельцем. Гость выбирает подходящий вариант (название и описание). Выбранный тип определяет длительность будущего слота.

3. **Открытие календаря на 14 дней**: После выбора типа встреча гостю открывается календарь, охватывающий текущую дату и следующие 13 календарных дней (всего 14 дней с сегодняшнего дня). Доступные слоты подсвечиваются в соответствии с часами работы владельца и часовым поясом, заданными как константы.

4. **Поиск свободных слотов**: Календарь показывает доступные временные интервалы в выбранную длительность. **Слоты отображаются в виде блоков**, которые гость может нажать для просмотра деталей. Показывается точное время начала и конца каждого слота.

5. **Бронирование слотa**: Гость нажимает на свободный слот — система мгновенно создает запись о бронировании. На экране появляется уведобление об успешной записи с деталями: тип встречи, дата, время, длительность.

6. **Соответствие длительности**: Длительность бронируемого слота строго соответствует длительности выбранного типа встречи. Если тип встречи задан как «30 минут», слот занимает ровно 30 минут с момента начала.

7. **Запрет на пересечение интервалов**: Система блокирует бронирование, если выбранное время уже занято другим типом встречи. Следующая встреча может начинаться в момент точного окончания предыдущей, но не раньше. Правила действуют и для двух запросов, пришедших одновременно.

8. **Появление записи у владельца**: Только что созданная гостем запись мгновенно появляется в списке запланированных встреч у владельца на его странице. Владелец видит запись с указанием типа встречи, даты и времени.

9. **Обработка одновременных запросов**: Если два гостя попытаются забронировать один и тот же слот одновременно, система обрабатывает запросы последовательно: первый запрос успешно записывает слот, второй запрос получает ответ о том, что слот уже занят, и предлагает альтернативные свободные варианты.

## Стек

- **BE**: Java 25, Spring Boot 4.1, Maven
- **FE**: React 19, TypeScript, Vite, Tailwind CSS 4, [shadcn/ui](https://ui.shadcn.com/)

## Установка

<!-- Опишите установку: клонирование, зависимости, переменные окружения -->

```bash
git clone https://github.com/DrPrimus/ai-for-developers-project-386.git
cd ai-for-developers-project-386
hk install --mise   # включить pre-commit хук
```

Запуск фронтенда (порт 80, подробности в `FE/README.md`):

```bash
mise run fe-run
```

Запуск бэкенда:

```bash
mise run be-run
```
